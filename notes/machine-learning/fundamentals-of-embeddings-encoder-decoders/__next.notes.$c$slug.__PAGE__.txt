<li>or next-token predicition (common for decoder models) -> decoder-based embeddings</li>
<li>or encoder-decoder model</li>
<li>or another large-scale language objective</li>
</ul>
</li>
<li>contrastive embedding training (learn similarities)
<ul>
<li>train on pairs or groups</li>
<li>query, positive, negative</li>
</ul>
</li>
</ul>
<p>during LLM (decoder architecture) pretraining:</p>
<ul>
<li>Also trains an embeddings model implicitly (but not specialized for similarity)</li>
<li>Every Transformer layer produces hidden vectors for the tokens
<ul>
<li>Those vectors contain information about the whole preceding context</li>
</ul>
</li>
</ul>
<hr>
<ul>
<li>
<p><strong>Yes, many dedicated embedding models are trained with contrastive learning.</strong></p>
<ul>
<li>Similar text pairs are pulled closer in vector space.</li>
<li>Unrelated text pairs are pushed farther apart.</li>
<li>Example:
<ul>
<li>“How do I reset my password?”</li>
<li>“Password reset instructions”</li>
<li>These should get nearby vectors.</li>
</ul>
</li>
</ul>
</li>
<li>
<p><strong>Embedding models are usually separate from GPT-style LLMs.</strong></p>
<ul>
<li>GPT model:
<ul>
<li>Main goal: predict the next token.</li>
<li>Usually decoder-only.</li>
<li>Output: text tokens.</li>
</ul>
</li>
<li>Embedding model:
<ul>
<li>Main goal: produce a useful vector for similarity/search.</li>
<li>Often encoder-only, though other architectures can work.</li>
<li>Output: one vector for the input text.</li>
</ul>
</li>
</ul>
</li>
<li>
<p><strong>But embedding models can still benefit from LLM-style pretraining.</strong></p>
<ul>
<li>Common process:
<ol>
<li>Pretrain a Transformer on lots of text.</li>
<li>Then train or fine-tune it with a contrastive embedding objective.</li>
</ol>
</li>
<li>So it can first learn language generally, then learn:
<ul>
<li>which sentences mean similar things,</li>
<li>which queries match which documents,</li>
<li>how to organize meaning in vector space.</li>
</ul>
</li>
</ul>
</li>
<li>
<p><strong>It does not have to be trained from a GPT model specifically.</strong></p>
<ul>
<li>GPT is decoder-only.</li>
<li>Many embedding models start from encoder models, such as BERT-like architectures.</li>
<li>Some modern systems also use decoder-only LLMs and adapt their hidden states into embeddings.</li>
<li>The important part is the final embedding-specific training objective, not whether it started as GPT.</li>
</ul>
</li>
</ul>
<h2 id="encoder-vs-decoder">Encoder vs decoder</h2>
<ul>
<li><strong>Encoder</strong>
<ul>
<li>Reads the input text.</li>
<li>Produces contextual vectors.</li>
<li>Usually can look at tokens on both sides of each token.</li>
<li>Good for:
<ul>
<li>embeddings,</li>
<li>classification,</li>
<li>search,</li>
<li>understanding text.</li>
</ul>
</li>
</ul>
</li>
</ul>
<pre><code class="language-text">text → encoder → vectors
</code></pre>
<ul>
<li><strong>Decoder</strong>
<ul>
<li>Generates tokens one at a time.</li>
<li>Looks at previous tokens and predicts the next one.</li>
<li>Good for:
<ul>
<li>writing,</li>
<li>answering questions,</li>
<li>generating code.</li>
</ul>
</li>
</ul>
</li>
</ul>
<pre><code class="language-text">previous tokens → decoder → next token
</code></pre>
<ul>
<li><strong>Encoder–decoder</strong>
<ul>
<li>The encoder reads and understands the input.</li>
<li>The decoder generates a new output based on the encoder’s representations.</li>
<li>Common for:
<ul>
<li>translation,</li>
<li>summarization,</li>
<li>text-to-text tasks.</li>
</ul>
</li>
</ul>
</li>
</ul>
<pre><code class="language-text">English sentence
      ↓
   encoder
      ↓
internal representations
      ↓
   decoder
      ↓
French sentence
</code></pre>
<p>Example:</p>
<pre><code class="language-text">Encoder reads:
"Translate 'hello' to French"

Decoder generates:
"bonjour"
</code></pre>
<h2 id="token-embeddings-vs-text-embeddings">Token embeddings vs text embeddings</h2>
<ul>
<li><strong>Token embedding</strong>
<ul>
<li>Represents one token.</li>
<li>A token may be:
<ul>
<li>a whole word,</li>
<li>part of a word,</li>
<li>punctuation,</li>
<li>a few characters.</li>
</ul>
</li>
<li>Example:</li>
</ul>
</li>
</ul>
<pre><code class="language-text">"unbelievable"

might become:
["un", "believ", "able"]
</code></pre>
<p>Each token gets its own starting vector.</p>
<ul>
<li><strong>Text embedding</strong>
<ul>
<li>Represents the meaning of the entire input.</li>
<li>It may summarize:
<ul>
<li>one sentence,</li>
<li>multiple sentences,</li>
<li>a paragraph,</li>
<li>a document chunk.</li>
</ul>
</li>
</ul>
</li>
</ul>
<pre><code class="language-text">"The dog is running through the park."
        ↓
one text embedding vector
</code></pre>
<h2 id="how-they-are-related">How they are related</h2>
<ul>
<li>Yes, they are related parts of the same processing pipeline.</li>
</ul>
<pre><code class="language-text">Text
 ↓
Tokenizer
 ↓
Token IDs
 ↓
Token embedding lookup
 ↓
One starting vector per token
 ↓
Transformer layers
 ↓
One contextual vector per token
 ↓
Pooling / projection
 ↓
One text embedding
</code></pre>
<ul>
<li>Step by step:
<ul>
<li>The tokenizer converts text into token IDs.</li>
<li>The token embedding table converts each token ID into a starting vector.</li>
<li>The Transformer modifies those vectors using context.</li>
<li>The final token vectors now contain contextual meaning.</li>
<li>The model combines those token vectors into one text embedding.</li>
</ul>
</li>
</ul>
<p>Example:</p>
<pre><code class="language-text">"The bank approved my loan"
</code></pre>
<p>Initial token vectors:</p>
<pre><code class="language-text">"The"  → vector
"bank" → vector
"approved" → vector
"my" → vector
"loan" → vector
</code></pre>
<p>After the Transformer, the vector for “bank” understands that it means a financial institution.</p>
<p>Then the model combines all the contextual token vectors into one vector representing the full sentence.</p>
<h2 id="the-simplest-distinction">The simplest distinction</h2>
<ul>
<li><strong>Token embedding:</strong> starting vector for one token.</li>
<li><strong>Contextual token representation:</strong> that token’s vector after Transformer processing.</li>
<li><strong>Text embedding:</strong> one combined vector representing the whole input.</li>
<li><strong>GPT output:</strong> probabilities over possible next tokens.</li>
</ul>
<p>So the full relationship is:</p>
<pre><code class="language-text">token embeddings are inputs to the Transformer

contextual token vectors are outputs of Transformer layers

text embeddings ar

e created by combining those contextual token vectors
