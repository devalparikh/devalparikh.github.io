<h1 id="local-llm-setup-on-m3-max-llamacpp--hugging-face">Local LLM Setup on M3 Max (llama.cpp + Hugging Face)</h1>
<h2 id="overview">Overview</h2>
<ul>
<li>Run open-source LLMs locally on M3 Max 36GB</li>
<li>Stack: <code>llama.cpp</code> for inference + <code>hf</code> CLI for model downloads</li>
<li>Exposes OpenAI-compatible API → drops into Codex, OpenCode, Aider, Continue</li>
<li>Claude Code support via LiteLLM proxy (Anthropic ↔ OpenAI translation)</li>
<li>MLX is a faster alternative for raw throughput — see <a href="/notes/tooling/local-llm-setup-on-m3-max/#alternative-runtimes">Alternative Runtimes</a></li>
<li>Analogy: <code>llama-server</code> is to local LLMs what Postgres is to local DBs — a daemon you point clients at</li>
</ul>
<h2 id="default-model-qwen36-27b">Default Model: Qwen3.6-27B</h2>
<ul>
<li><strong>Top pick for 36GB</strong> as of Apr 2026
<ul>
<li>27B dense, ~16GB at Q4_K_M</li>
<li>Beats prior-gen Qwen3.5-397B-A17B on coding benchmarks</li>
<li>262k native context (extensible to 1M)</li>
<li>Apache 2.0</li>
<li>GGUF community quants already published</li>
</ul>
</li>
</ul>
<h2 id="setup-steps">Setup Steps</h2>
<h3 id="1-install-both-tools">1. Install both tools</h3>
<pre><code class="language-bash">brew install llama.cpp hf
</code></pre>
<ul>
<li><code>llama.cpp</code> ships with Metal enabled by default on macOS</li>
<li><code>hf</code> is the renamed HuggingFace CLI (was <code>huggingface-cli</code>)</li>
</ul>
<h3 id="2-authenticate-with-hugging-face">2. Authenticate with Hugging Face</h3>
<pre><code class="language-bash">hf auth login
</code></pre>
<ul>
<li>Token from <a href="https://huggingface.co/settings/tokens" target="_blank" rel="noopener noreferrer">https://huggingface.co/settings/tokens</a></li>
<li>Required for gated models (Gemma, Llama) — also accept license on the model page in browser first</li>
</ul>
<h3 id="3-download-a-model-gguf-format">3. Download a model (GGUF format)</h3>
<ul>
<li>
<p><strong>Coding default</strong> — Qwen3.6-27B (~16GB):</p>
<pre><code class="language-bash">hf download unsloth/Qwen3.6-27B-GGUF \
  Qwen3.6-27B-Q4_K_M.gguf \
  --local-dir ~/models
</code></pre>
</li>
<li>
<p><strong>General</strong> — Gemma 3 27B (~16GB):</p>
<pre><code class="language-bash">hf download bartowski/gemma-3-27b-it-GGUF \
  gemma-3-27b-it-Q4_K_M.gguf \
  --local-dir ~/models
</code></pre>
</li>
<li>
<p>Quant cheat sheet for 36GB:</p>
<ul>
<li><code>Q4_K_M</code> → default, best size/quality tradeoff</li>
<li><code>Q5_K_M</code> → +25% size, slight quality bump</li>
<li><code>IQ4_XS</code> → smaller, near Q4_K_M quality (uses imatrix)</li>
<li><code>Q8_0</code> → near-lossless, only viable for ≤14B models</li>
</ul>
</li>
</ul>
<h3 id="4-run-the-server-openai-compatible-api">4. Run the server (OpenAI-compatible API)</h3>
<pre><code class="language-bash">llama-server \
  -m ~/models/Qwen3.6-27B-Q4_K_M.gguf \
  -ngl 99 \
  -c 16384 \
  --flash-attn on \
  --cache-type-k q8_0 \
  --cache-type-v q8_0 \
  --port 8080
</code></pre>
<ul>
<li>Endpoint live at <code>http://localhost:8080/v1</code></li>
<li>Critical flags:
<ul>
<li><code>-ngl 99</code> → all layers on GPU (Metal). <strong>Always set this</strong></li>
<li><code>--flash-attn on</code> → ~30% speedup, lower memory (use <code>on|off|auto</code>, no longer a bare toggle)</li>
<li><code>--cache-type-k/v q8_0</code> → halves KV cache memory</li>
<li><code>-c 16384</code> → 16k context (KV cache scales linearly, only bump if needed)</li>
<li><code>--mlock</code> → optional, pins model in RAM, prevents macOS swapping</li>
</ul>
</li>
</ul>
<h3 id="5-wire-into-agentic-coding-tools">5. Wire into agentic coding tools</h3>
<h4 id="opencode-recommended--native-openai-compatible-no-proxy">OpenCode (recommended — native OpenAI-compatible, no proxy)</h4>
<ul>
<li>Install:
<pre><code class="language-bash">npm install -g opencode-ai
# or: brew install sst/tap/opencode
</code></pre>
</li>
<li>Configure <code>~/.config/opencode/opencode.json</code>:
<pre><code class="language-json">{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "local": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Local llama.cpp",
      "options": {
        "baseURL": "http://localhost:8080/v1",
        "apiKey": "dummy"
      },
      "models": {
        "qwen3.6-27b": {
          "name": "Qwen3.6 27B (local)"
        }
      }
    }
  }
}
</code></pre>
</li>
<li>Run: <code>opencode</code> → use <code>/models</code> to pick <code>local/qwen3.6-27b</code></li>
<li>Quick env-var alternative (no config file):
<pre><code class="language-bash">export OPENAI_BASE_URL=http://localhost:8080/v1
export OPENAI_API_KEY=dummy
opencode
</code></pre>
</li>
</ul>
<h4 id="codex--aider-also-openai-compatible">Codex / Aider (also OpenAI-compatible)</h4>
<pre><code class="language-bash">export OPENAI_BASE_URL=http://localhost:8080/v1
export OPENAI_API_KEY=dummy
</code></pre>
<h4 id="claude-code-needs-anthropic--openai-proxy">Claude Code (needs Anthropic ↔ OpenAI proxy)</h4>

<h4 id="tool-call-expectations">Tool-call expectations</h4>
<ul>
<li><strong>OpenCode</strong>: best of the bunch for local — provider-aware, handles smaller-model quirks</li>
<li><strong>Claude Code</strong>: works but rough — Claude Code expects frontier-model quality tool calls; expect malformed JSON occasionally</li>
<li><strong>All tools</strong>: bump <code>-c</code> to 64k+ for usable agentic work (tools eat context fast)</li>
<li>If tool calls fail repeatedly → add <code>--chat-template chatml</code> to llama-server</li>
</ul>
<h3 id="6-verify-performance">6. Verify performance</h3>
<pre><code class="language-bash">llama-bench -m ~/models/Qwen3.6-27B-Q4_K_M.gguf -ngl 99 -fa 1
</code></pre>
<ul>
<li>Expected on M3 Max for 27B Q4_K_M:
<ul>
<li>Prompt eval: ~200–400 tok/s</li>
<li>Generation: ~18–22 tok/s</li>
</ul>
</li>
<li>If gen &#x3C;10 tok/s → swapping. Close Chrome/Docker, check <code>sudo memory_pressure</code></li>
</ul>
<h2 id="optimization-knobs-matter-a-lot">Optimization Knobs (matter a lot)</h2>
<ul>
<li><strong>Quant level</strong>: 4-bit is the sweet spot. Below 4-bit = noticeable quality loss</li>
<li><strong>Context length</strong>: KV cache scales linearly. Drop to 8k–16k unless you need long context</li>
<li><strong>Flash attention</strong>: always enable on M-series (<code>--flash-attn on</code>)</li>
<li><strong>KV cache quantization</strong>: <code>q8_0</code> halves memory with negligible quality hit</li>
<li><strong>Speculative decoding</strong>: pair big model with tiny draft model → 1.5–2x speedup
<ul>
<li>Example: 27B target + 1.5B draft, both same family</li>
<li>Best gains on predictable text (code, structured output)</li>
</ul>
</li>
<li><strong>Memory pressure</strong>: keep ~6GB free for macOS or you'll swap and tank tok/s</li>
<li><strong>Unified memory caveat</strong>: Chrome/Docker/etc fight for the same pool. Close before long sessions</li>
</ul>
<h2 id="speculative-decoding-example">Speculative Decoding Example</h2>
<pre><code class="language-bash">llama-server \
  -m ~/models/Qwen3.6-27B-Q4_K_M.gguf \
  -md ~/models/Qwen3-1.5B-Q4_K_M.gguf \
  -ngl 99 -ngld 99 \
  --draft-max 16 --draft-min 4 \
  --flash-attn on -c 8192
</code></pre>
<ul>
<li>Draft model generates N tokens, big model verifies in one pass</li>
<li><code>-md</code> = draft model path, <code>-ngld</code> = draft model GPU layers</li>
</ul>
<h2 id="models-that-wont-fit-on-36gb">Models That Won't Fit on 36GB</h2>
<p>These are the current frontier open models — all need data-center GPUs:</p>
<ul>
<li><strong>Kimi K2.6</strong> (Moonshot) — 1T total / 32B active MoE
<ul>
<li>Smallest viable quant: 350GB (2-bit dynamic GGUF)</li>
<li>Needs 8x H100 for production</li>
</ul>
</li>
<li><strong>DeepSeek-V4-Pro</strong> — 1.6T total / 49B active MoE
<ul>
<li>1M-token context with hybrid CSA/HCA attention</li>
<li>Even V4-Flash (284B/13B active) needs ~140GB at 4-bit</li>
</ul>
</li>
<li><strong>GLM-5.1</strong> (zai-org) — 754B total / 40B active MoE
<ul>
<li>Smallest quant (Unsloth dynamic 1-bit): 200GB</li>
<li>Strong on SWE-Bench Pro and Terminal-Bench 2.0</li>
</ul>
</li>
</ul>
<blockquote>
<p>warning: MoE saves compute, <strong>not memory</strong>. All experts must stay resident. Active param count (the smaller number) only tells you inference cost, not RAM requirement.</p>
</blockquote>
<p>For these models: use APIs (OpenRouter, DeepInfra, provider direct) instead of local hosting.</p>
<h2 id="other-models-that-fit-on-36gb">Other Models That Fit on 36GB</h2>
<ul>
<li><strong>Gemma 3 27B</strong> (~16GB at 4-bit) — strong general reasoning, multimodal</li>
<li><strong>Qwen2.5-Coder 32B</strong> (~18GB at 4-bit) — previous default, still solid</li>
<li><strong>Llama 3.3 70B</strong> at IQ2_XXS (~22GB) — pushes limits, slower, quality dips noticeably</li>
<li><strong>Qwen3 14B / Gemma 3 12B</strong> at 4-bit — fast, leaves headroom for big context</li>
</ul>
<h2 id="common-gotchas">Common Gotchas</h2>
<ul>
<li>Forgot <code>-ngl 99</code> → runs on CPU, 10x slower</li>
<li>Context too large → OOM crash. Watch <code>sudo memory_pressure</code> while running</li>
<li>Wrong chat template → garbage output. Pass <code>--chat-template chatml|llama3|gemma</code> if auto-detect fails</li>
<li>Gated model 401 → accept license in browser first, even with valid token</li>
<li>Partial GGUF download → cryptic errors. Verify <code>ls -lh</code> matches HF size</li>
<li><strong>Flag drift</strong>: llama.cpp renames flags often. Recent breakage:
<ul>
<li><code>--flash-attn</code> → now requires value: <code>--flash-attn on|off|auto</code></li>
<li>Run <code>llama-server -h | grep &#x3C;flag></code> if a flag errors</li>
</ul>
</li>
</ul>

<h2 id="alternative-runtimes">Alternative Runtimes</h2>
<ul>
<li><strong>MLX / <code>mlx-lm</code></strong> — Apple's native framework, ~10–30% faster on Apple Silicon
<ul>
<li>Separate runtime, separate model format (MLX folder, <strong>not GGUF</strong> — no interop with llama.cpp)</li>
<li>Use when raw throughput matters more than ecosystem/quant variety</li>
<li>Install: <code>pip install mlx-lm --break-system-packages</code></li>
<li>Download: <code>hf download unsloth/Qwen3.6-27B-UD-MLX-4bit --local-dir ~/models/qwen3.6-mlx</code></li>
<li>Run: <code>mlx_lm.server --model ~/models/qwen3.6-mlx --port 8080</code></li>
<li>Tradeoffs: smaller model selection, fewer quant variants, no spec decoding yet</li>
</ul>
</li>
<li><strong>Ollama</strong> — wraps llama.cpp, easier ergonomics, model registry
<ul>
<li>Use as always-on daemon: <code>brew install ollama &#x26;&#x26; ollama serve</code></li>
<li>Endpoint at <code>http://localhost:11434/v1</code></li>
</ul>
</li>
<li><strong>LM Studio</strong> — GUI for browsing/comparing quants
<ul>
<li>Bundles both MLX and llama.cpp runtimes (pick per model)</li>
</ul>
</li>
</ul>
