11:Te14,<h2 id="background">Background</h2>
<p>Language: Java</p>
<p>Usages:</p>
<ul>
<li><a href="/notes/distributed-systems/microservices/">Microservices</a></li>
<li><a href="/notes/distributed-systems/patterns/event-driven-architecture/">Event-Driven Architecture</a></li>
<li>Dependency Injection</li>
</ul>
<p>Description</p>
<ul>
<li>A dependency injection framework for Java that has many web and backend plugins</li>
</ul>
<h2 id="types">Types</h2>
<h3 id="reactive">Reactive</h3>
<ul>
<li><strong><a href="/notes/code/java/spring-webflux-reactive/">Spring WebFlux (Reactive)</a></strong></li>
<li><strong>Asynchronous threads</strong>, non-blocking, event loop</li>
<li><a href="/notes/distributed-systems/patterns/event-driven-architecture/">Event-Driven Architecture</a></li>
<li>Netty</li>
<li>Request gets assigned to thread</li>
<li>Functional Programming / Reactive Programming</li>
<li>Complex to code, but more thread efficient</li>
<li>HTTP Client: WebClient</li>
</ul>
<h3 id="servlet">Servlet</h3>
<ul>
<li><strong>Spring MVC</strong></li>
<li><strong>Synchronous threads</strong> (blocking)</li>
<li>Thread per request</li>
<li>Imperative Programming</li>
<li>Simpler to code, but less efficient</li>
<li>HTTP Client: RestTemplate (deprecated)</li>
</ul>
<h3 id="examples">Examples</h3>
<ul>
<li>Restaurant
<ul>
<li>Reactive:
<ol>
<li>server takes queue of orders (events)</li>
<li>cook "subscribes" to queue of meals to prepare</li>
<li>cook "publishes" to waiters queue to serve once meal is done</li>
</ol>
<ul>
<li>each threads are optimally used</li>
</ul>
</li>
<li>Servlet:
<ol>
<li>server takes order</li>
<li>cook prepares (30min)</li>
<li>serve food</li>
<li>repeat</li>
</ol>
<ul>
<li>each order is a new thread</li>
</ul>
</li>
</ul>
</li>
</ul>
<h2 id="springboot">SpringBoot</h2>
<p>SpringBoot is a bootstrap for Spring</p>
<h2 id="spring-security">Spring Security</h2>
<p>OAuth implementation built in to Spring</p>
<h3 id="classes">Classes</h3>
<ul>
<li>Principal: Authentication Object (Bearer Token)</li>
<li>UserDetails: User Object</li>
<li><a href="https://github.com/devalparikh/GeoGram/tree/main/backend/src/main/java/com/deval/test/mongoDB/spring/backend/AuthUser" target="_blank" rel="noopener noreferrer">Geogram Example Implementation</a></li>
</ul>
<h2 id="thread-safety">Thread Safety</h2>
<p><a href="https://stackoverflow.com/questions/43314831/spring-boot-class-behaviour" target="_blank" rel="noopener noreferrer">https://stackoverflow.com/questions/43314831/spring-boot-class-behaviour</a></p>
<ul>
<li>When using @Bean @Autowired or any method of creating a singleton class, one instance will be created and shared for the entire application (unless @Scope is defined)</li>
<li>Each request to the application is a on its own thread</li>
<li>Static variables by nature are shared amongst all instances, so it is shared amongst all threads</li>
<li>Class-level variables will be shared amongst all threads for a singleton, since it's one shared instance of the class used for all requests</li>
<li>For data that should not be shared, create a new instance of that non singleton class every time (not a bean)</li>
<li><strong><code>@Scope(value="request")</code></strong></li>
<li>If the data needs to be shared but thread safe: <a href="https://www.baeldung.com/java-thread-safety" target="_blank" rel="noopener noreferrer">https://www.baeldung.com/java-thread-safety</a>
<ul>
<li>Stateless static methods (just takes an input)</li>
<li>Atomic objects, like AtomicInteger</li>
<li>Immutable variables (private final and use a getter)</li>
</ul>
</li>
