5:T1227,<h1 id="policy-based-authorization">Policy-based Authorization</h1>
<h2 id="background">Background</h2>
<p>In ASP.NET Core, policy-based authorization is a flexible way to enforce access control. It involves <strong>requirements</strong>, <strong>handlers</strong>, and <strong>policies</strong>.</p>
<p>under the hood, <a href="https://learn.microsoft.com/en-us/aspnet/core/security/authorization/roles?view=aspnetcore-9.0" target="_blank" rel="noopener noreferrer">role-based authorization</a> and <a href="https://learn.microsoft.com/en-us/aspnet/core/security/authorization/claims?view=aspnetcore-9.0" target="_blank" rel="noopener noreferrer">claims-based authorization</a> use a requirement and a preconfigured policy</p>
<h3 id="requirement">Requirement</h3>
<p>resembles an authorization requirement
the logic is implemented by a handler(s)
the requirement is consumed in a policy</p>
<pre><code class="language-csharp">public class MinimumAgeRequirement : IAuthorizationRequirement
{
    public int MinimumAge { get; }
    public MinimumAgeRequirement(int minimumAge) => MinimumAge = minimumAge;
}
</code></pre>
<h3 id="handler">Handler</h3>
<p>responsible for evaluation logic for requirement(s)
the handler is registered in DI</p>
<pre><code class="language-csharp">public class MinimumAgeHandler : AuthorizationHandler&#x3C;MinimumAgeRequirement>
{
    protected override Task HandleRequirementAsync(
        AuthorizationHandlerContext context,
        MinimumAgeRequirement requirement)
    {
        if (context.User.HasClaim(c => c.Type == "Age"))
        {
            int age = int.Parse(context.User.FindFirst(c => c.Type == "Age").Value);
            if (age >= requirement.MinimumAge)
            {
                context.Succeed(requirement);
            }
        }
        return Task.CompletedTask;
    }
}
</code></pre>
<h3 id="policy-registration">Policy (Registration)</h3>
<pre><code class="language-csharp">builder.Services.AddAuthorization(options =>
{
    options.AddPolicy("AdultOnly", policy =>
        policy.Requirements.Add(new MinimumAgeRequirement(18)));
});

builder.Services.AddSingleton&#x3C;IAuthorizationHandler, MinimumAgeHandler>();
</code></pre>
<p><a href="https://learn.microsoft.com/en-us/aspnet/core/security/authorization/policies?view=aspnetcore-9.0#why-would-i-want-multiple-handlers-for-a-requirement" target="_blank" rel="noopener noreferrer">Register a handler</a></p>
<h3 id="usage">Usage</h3>
<pre><code class="language-csharp">[Authorize(Policy = "AdultOnly")]
public IActionResult RestrictedAccess()
{
    return Ok("You have access!");
}
</code></pre>
<pre><code class="language-csharp">var authResult = await _authorizationService.AuthorizeAsync(User, null, "AdultOnly");
if (authResult.Succeeded)
{
    // Grant access
}
</code></pre>
<p>Use <a href="https://learn.microsoft.com/en-us/dotnet/api/microsoft.aspnetcore.authorization.iauthorizationservice" target="_blank" rel="noopener noreferrer">IAuthorizationService</a>, <code>[Authorize(Policy = "Something")]</code>, or <code>RequireAuthorization("Something")</code> for authorization.</p>
<h2 id="mapping">Mapping</h2>
<p>different types are handler -> requirement mapping</p>
<p><strong>One-to-one Authorization</strong></p>
<ul>
<li>[one handler for one requirement](A requirement can have multiple handlers. A handler may inherit AuthorizationHandler, where TRequirement is the requirement to be handled. Alternatively, a handler may implement IAuthorizationHandler directly to handle more than one type of requirement.)</li>
</ul>
<p><strong>One-to-many Authorization</strong> (<strong>"AND" Authorization</strong>)</p>
<ul>
<li><a href="https://learn.microsoft.com/en-us/aspnet/core/security/authorization/policies?view=aspnetcore-9.0#use-a-handler-for-multiple-requirements" target="_blank" rel="noopener noreferrer">one handler for multiple requirements</a></li>
<li>policy has multiple requirements</li>
<li>handler has logic to handle multiple requirements</li>
</ul>
<p><strong>Many-to-one Authorization</strong> (for <strong>"OR" Authorization (chain)</strong>)</p>
<ul>
<li>many handlers per requirement</li>
<li>policy has 1 requirement, but many handlers as options to fulfill the requirement</li>
<li>uses <code>public class [Badge/TempBadge]EntryHandler : AuthorizationHandler&#x3C;BuildingEntryRequirement></code></li>
<li><a href="https://learn.microsoft.com/en-us/aspnet/core/security/authorization/policies?view=aspnetcore-9.0#why-would-i-want-multiple-handlers-for-a-requirement" target="_blank" rel="noopener noreferrer">multiple handlers requirement</a></li>
<li>register both handlers</li>
