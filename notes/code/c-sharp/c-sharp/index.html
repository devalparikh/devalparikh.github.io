Basics

Terms

  • Type - blueprint defines structure (value type and reference type)
    • Class - reference type
    • (Member - general term refers to elements in a class (such as: fields, methods, etc))
    • Field - variable in a class (assigned a type)
    • Property - mechanism to read/write/compute on private field (include accessor methods) (getters/setters)
    • Attribute - metadata applied to classes, methods, properties (not data storage, but metadata)

Type

  • Value Type (primitive)
    • Kinda like primitives
    • Memory: allocated on stack
    • Garbage Collection: not managed
    • Upon assignment to another variable: copy value
    • null: not allowed (?)
    • Examples: int, float, bool, char, struct, enum
  • Reference Type (class)
    • Memory: allocated on heap
    • Garbage Collection: managed
    • Upon assignment to another variable: shared memory
    • null: allowed
    • Examples: class, interface, delegate, array, string
  • Type Members
    • Fields: Variables that hold data
    • Properties: Accessors for fields
    • Methods: Functions that perform operations
    • Events: Notifications that something has occurred
    • Constructors: Methods called when an instance is created
    • Destructors: Methods called when an instance is destroyed

Data Structures

  • record - immutable
  • struct - stored in stack (good for small to save memory)
  • class - stored in heap (functionality)

Keywords

General

public - Accessible from any other code in the same assembly or referencing assembly private - Accessible only within the same class or struct protected - Accessible within the same class and derived classes internal - Accessible within the same assembly static - Belongs to the type itself, not to a specific object instance

Classes

abstract - Cannot be instantiated, may contain abstract methods sealed - Cannot be inherited from

partial - Allows splitting a class definition across multiple files virtual - Can be overridden by derived classes override - Implements a method of an abstract class or overrides a virtual method new - Hides an inherited member from a base class

class - Defines a reference type struct - Defines a value type (stored in stack)

  • details
    • good for small
    • good for immutable value types
    • improves performance (stack memory)
    • saves memory (stack memory)
    • copy by value record - Defines an immutable reference type with value-based equality (immutable) interface - Defines a contract that classes can implement enum - Defines a set of named constants

Fields

readonly - Can only be assigned in declaration or constructor (immutable)

  • details
    • compiler optimization const - Compile-time constant (immutable)
  • details
    • saves memory
    • compiler optimization
    • no stack or heap volatile - Indicates that a field might be modified by multiple threads fixed - Used in unsafe code to prevent the garbage collector from relocating a variable event - Declares an event

Methods

virtual - Can be overridden by derived classes override - Implements a method of an abstract class or overrides a virtual method abstract - Must be implemented by derived classes sealed - Cannot be overridden further in derived classes new - Hides an inherited member from a base class async - Method contains asynchronous operations extern - Method is implemented externally partial - Allows splitting a method definition across multiple files unsafe - Allows use of pointer types within the method ref - Parameter is passed by reference in - Parameter is passed by reference, but cannot be modified out - Parameter is passed by reference and must be assigned before method returns

Implicit Operator

Allows a method to return multiple types of objects

public class Result<T>
{
    public T Value { get; }
    public Error Error { get; }
    public bool IsSuccess { get; }

    private Result(T value)
    {
        Value = value;
        IsSuccess = true;
    }

    private Result(Error error)
    {
        Error = error;
        IsSuccess = false;
    }

	// implicit operators
    public static implicit operator Result<T>(T value) 
    => new Result<T>(value);
    
    public static implicit operator Result<T>(Error error) 
    => new Result<T>(error);
}

public class Error
{
    public string Code { get; }
    public string Message { get; }

    public Error(string code, string message)
    {
        Code = code;
        Message = message;
    }
}

// usage example
public class Example 
{
	public Result<User> GetUser(Guid id)
	{
	    if (_users.TryGetValue(id, out var user))
	    {
		    // Implicitly converted to Result<User>
	        return user;
	    }
		// Implicitly converted to Result<User>
	    return new Error("NotFound", "User not found");
	}
}

Best Practices

  • var
    • If right side is defined, can be used to shorten code
    • only use when it is very obvious what the type is
    • iEnumerable<Person> vals = ... vs iEnumerable<Pet> vals = ...
      • do not use var for things like this, because it will be unclear if it is vals of person or pets
    • cons
      • decreases readability by avoiding having to hover and check type

Naming Convention

  • PascalCase for types, namespaces, and all public members
  • camelCase for method parameters and local variables
  • _camelCase for private private instance fields
  • PascalCase for constant names, both fields and local constants
  • s_camelCase private static
  • t_camelCase private thread static
  • Interface start with I
  • Attribute types end with the word Attribute
  • Namespace end with the word Namespace
