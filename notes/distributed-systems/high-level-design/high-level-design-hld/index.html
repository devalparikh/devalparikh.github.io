High Level Design (HLD)

Overview

two types

  • product
  • infrastructure

Steps

  1. Requirements
  2. Core Entities
  3. API
  4. High-level Design
  5. Deep Dives

Requirements

Functional Requirements - features Non-functional Requirements - user experience

  • Latency
  • CAP Theorem - strong consistency vs high availability
    • Strong consistency for xyz feature
    • High availability for abc feature
    • ex: booking system (working during network partition)
      • strong consistency
      • when user tries during parallel acid write, user sees error (lost availability)
  • Read Write Ratio
  • Scale (customize for app)
    • Scalability to handle surges from popular events
  • Fault tolerance

Core Entities

  • 1 entity maps to 1 service in microservices
  • ex: booking system
    • Event
    • Venue
    • Ticket
    • Performer

  • Horizontal scaling
