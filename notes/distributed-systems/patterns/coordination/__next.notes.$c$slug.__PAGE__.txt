5:T7d0,<p>In distributed systems, often times a central coordination service is needed between nodes.</p>
<h1 id="apache-zookeeper">Apache ZooKeeper</h1>
<p>Apache ZooKeeper is an example of a coordination service that can be used to coordinate nodes.</p>
<h1 id="use-case">Use Case</h1>
<h2 id="nosql-with-strong-consistency-for-unique-id-generation">NoSQL with Strong Consistency for Unique Id Generation</h2>
<ul>
<li>This example stems from the URL Shortener system design, where a unique id needs to be created but ensured it's not in use
<ul>
<li>in SQL we are ACID compliant and can use putIfAbsent for <a href="/notes/distributed-systems/databases/consistency/#strong-consistency-read-after-write">Strong consistency (read after write)</a></li>
<li>in NoSQL, we are running on <a href="/notes/distributed-systems/databases/consistency/#eventual-consistency">Eventual consistency</a> due to the nature of how it scales horizontally</li>
<li>Checking if it exists each new post / put request is expensive and not viable</li>
</ul>
</li>
<li>We want to use NoSQL for the scalability, but can not have eventual consistency as it is a risk of having collision, this is how we can achieve <strong>NoSQL with Strong Consistency</strong> when generating ids:
<ol>
<li>A <strong>number from a counter</strong> can be used to <strong>create random unique ids</strong> (using encoding or hashing) and <strong>ensure it has not been used before</strong> (since it increments)</li>
<li>Lets say you have an application with many instances / nodes and is regionally distributed and we need to keep track of a counter 1 - 100,000,000 between all instances and be synchronized</li>
<li>We can use ZooKeeper to coordinate
instance 1 counts: 0 - 10,000,000
instance 2 counts: 10,000,001 - 20,000,000
...
and when an instance counter reaches the limit, the coordination service will tell the instance the next range to use
and if an instance goes down, that range will simply be unused or paused</li>
</ol>
</li>
