5:T67e,<p>Hashing allows us to map a key to a number that represents a node</p>
<p>In large scale systems, one cluster (cache cluster, server cluster, db cluster) is not enough</p>
<p>Hashing can be used to determine which node should be used for the given request</p>
<h1 id="simple-hashing">Simple Hashing</h1>
<ul>
<li>HashFunction(key) % N</li>
<li>N is number of nodes</li>
<li>HashFunction looks to distribute evenly</li>
<li><strong>Issue</strong>: what if N changes, <strong>all keys are now corrupt</strong> as the same node won't be used</li>
</ul>
<h1 id="consistent-hashing">Consistent Hashing</h1>
<ul>
<li>Aimed to have consistent node assignment even has N changes</li>
<li>Hash the <strong>key</strong> and <strong>server name</strong></li>
<li>Range of x0 to xN (Hash Space)</li>
<li>Implementation
<ul>
<li>Make 0->N in a ring</li>
<li>HashFunction(server name/ip)</li>
<li>HashFunction(key)</li>
<li>Retrieve
<ul>
<li>Find Hash of key and go clockwise until a server found</li>
</ul>
</li>
<li>If N changes, <strong>only one range</strong> of keys gets lost</li>
<li><strong>Issue</strong>: distribution of objects may be <strong>uneven</strong>
<ul>
<li>Solution: Virtual Nodes, spread apart a single node on the ring as virtual nodes</li>
<li>Now nodes won't be starved of traffic</li>
<li>Takes metadata for maintaining virtual nodes</li>
</ul>
</li>
</ul>
</li>
<li>Real life usages
<ul>
<li>DynamoDB and Cassandra - Data Partitioning
<ul>
<li>Minimizes data movement during rebalances</li>
</ul>
</li>
<li>Content Delivery Networks - Distribute web content</li>
<li>Load Balancer - Distribute persistent connections evenly</li>
</ul>
</li>
