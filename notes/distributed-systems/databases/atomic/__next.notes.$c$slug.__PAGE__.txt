5:T939,<p><strong>atomic</strong> = all or nothing
distributed transactions</p>
<ul>
<li>transaction - an operation</li>
<li>distributed - one operation made up of many operations on multiple decoupled systems
transactional = atomic = all or nothing</li>
</ul>
<p>example: transactions to withdraw from bank A and save to bank B (either all are complete, or non complete), shouldn’t be a case where half is complete when reading.</p>
<h2 id="distributed-transactions-atomic">Distributed transactions (atomic)</h2>
<p>a way to determine should a transaction commit across all participants (ensuring all participants agree and are on the same page)</p>
<ul>
<li><strong>2-phase commit</strong> (strong atomicity)
<ul>
<li>2 steps
<ul>
<li>prepare / vote</li>
<li>commit</li>
</ul>
</li>
<li>all databases are atomic and when 1 database aborts, the entire transaction to all databases aborts</li>
<li>Helps have ACID in distributed databases</li>
<li><a href="https://medium.com/geekculture/distributed-transactions-two-phase-commit-c82752d69324" target="_blank" rel="noopener noreferrer">https://medium.com/geekculture/distributed-transactions-two-phase-commit-c82752d69324</a></li>
<li>Acts as a single ACID commit</li>
<li>problem: if coordinator dies before telling everyone, then all participants are idle</li>
</ul>
</li>
<li><strong>3-phase commit</strong> (strong atomicity)
<ul>
<li>3 steps
<ul>
<li>prepare / vote</li>
<li>pre-commit</li>
<li>commit</li>
</ul>
</li>
<li>solves problem of 2-phase commit, middle step of pre-commit, where coordinator will broadcast to all participants on the decision. so participants know safe to commit
<ul>
<li>Adds a pre-commit phase to reduce blocking if the coordinator crashes
<ul>
<li>participants can coordinate with each other to recognize theyve all reached pre-commit and can finish commit without coordinator</li>
</ul>
</li>
<li>This allows participants to use timeouts and their known protocol states to recover</li>
</ul>
</li>
</ul>
</li>
<li><strong><a href="/notes/distributed-systems/patterns/saga/">SAGA</a></strong> (eventual atomicity)
<ul>
<li>Multiple commits sequentially (and rolling back each step upon failure)</li>
<li>Simulates distributed transactions by having the programming model simulate consistency</li>
<li>Need a state field in the db usually (to say it’s done)</li>
</ul>
</li>
