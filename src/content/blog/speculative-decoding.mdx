The small AI is allowed to be wrong. Its guesses never become final text until the large AI checks them.

When the guesses are good, one expensive check can return several pieces of text. The large AI still decides what is allowed.

That is speculative decoding.

## Why text generation is slow

A <TechnicalTerm definition="A system that predicts the next piece of text from the text it has already seen.">language model</TechnicalTerm> writes one <TechnicalTerm definition="A small piece of text. It can be a word, part of a word, or punctuation.">token</TechnicalTerm> at a time.

It cannot choose token 2 until token 1 exists. It cannot choose token 3 until token 2 exists. The work forms a line:

```text
large model -> "The"
large model -> "cat"
large model -> "sat"
large model -> "nearby"
```

Servers remember earlier calculations, so the model does not start over for every token. But the waiting remains. Each new token depends on the one before it.

## Guess first, check together

Speculative decoding adds a <TechnicalTerm definition="The small, fast model that guesses a few tokens ahead.">draft model</TechnicalTerm>. This small model guesses several tokens first.

The <TechnicalTerm definition="The large model whose output probabilities must be preserved.">target model</TechnicalTerm> then checks those positions in one pass. Modern AI hardware is good at doing similar calculations together. This is called <TechnicalTerm definition="Doing several calculations at the same time instead of waiting for each one to finish.">parallel work</TechnicalTerm>.

The draft adds work. That sounds backward, but the added work is cheap. It can save time by reducing how often the large model must run in sequence.

## What happens to a bad guess

The small model guesses:

```text
The cat sat down
```

The large model prefers:

```text
The cat sat nearby
```

Tap the verbs to see the sentence change.

<SpeculativeRoundExplorer />

The system reads the guesses from left to right. It keeps the good <TechnicalTerm definition="The accepted tokens from the start of a proposed sequence.">prefix</TechnicalTerm>, which means the accepted tokens at the start.

It stops at the first bad guess. That position now needs a new token. The <TechnicalTerm definition="The step that replaces a rejected guess using chances the small model missed.">repair step</TechnicalTerm> picks it. Any guess after it is thrown away because those later guesses were based on text the large model rejected.

If every guess passes, the large model can add one more token. It already calculated the next position while checking the draft.

## Why the repair is needed

In the previous section, the system rejected `down`. That leaves an empty slot after `The cat sat`.

The system cannot simply ask the small model again. The small model guesses some words too often and others too rarely. It also cannot make a fresh normal pick with the large model. The accepted guesses have already used some of the large model's chances.

That is the repair's job. It fills the empty slot using only the chances the small model missed. This lets the shortcut save work without changing the large model's original chances.

The large model does not have one fixed next word. For one position, picture its chances as 100 points:

- 50 points for `cat`
- 30 points for `dog`
- 20 points for `owl`

The small model uses the same 100 points, but gets the split wrong. It gives 60 to `cat`, 10 to `dog`, and 30 to `owl`.

The check keeps only the points that fit inside the large model's split:

- It keeps 50 `cat` points. The extra 10 do not fit.
- It keeps 10 `dog` points. That is all the small model supplied.
- It keeps 20 `owl` points. The extra 10 do not fit.

Only 80 points remain. If the system stopped here, `dog` would be too rare. The small model would have changed the answer.

The system cannot make a fresh 50, 30, 20 pick for the empty space. `cat` and `owl` already have all their points. Only `dog` is short. The repair adds the missing 20 `dog` points.

<ExactnessVisual />

The final split is back to 50 `cat`, 30 `dog`, and 20 `owl`. The technical name for this list of chances is a <TechnicalTerm definition="A list of possible outcomes and the chance assigned to each one.">probability distribution</TechnicalTerm>.

Without the repair, the small model would change which words appear. With the repair, the shortcut changes the work, not the large model's chances. That is what "exact" means here.

The system then makes one random pick from those chances. This is called <TechnicalTerm definition="Randomly choosing a token using the chances assigned by the model.">sampling</TechnicalTerm>. Two runs can pick different words. Across many runs, each word appears at the large model's original rate.

## When it is faster

Speculative decoding usually helps when:

- the draft model is much cheaper than the target model;
- the draft and target agree often;
- the hardware can check a short group of positions efficiently.

It can be slower when the first guess often fails, the draft model is too large, or moving data between models costs more than the saved target passes.

Serving many users adds another tradeoff. A setup can improve <TechnicalTerm definition="How long one request waits for output.">latency</TechnicalTerm> for one request while hurting <TechnicalTerm definition="How much total output the system produces across all requests.">throughput</TechnicalTerm> for the whole server. Both need to be measured.

## Measured speedups

[Leviathan, Kalman, and Matias](https://arxiv.org/abs/2211.17192v2) measured about `2x to 3x` faster decoding on T5-XXL in their test setups.

[Chen and coauthors](https://arxiv.org/abs/2302.01318v1) measured about `2x to 2.5x` faster decoding in their Chinchilla experiments.

Those results show that the method can work. They are not a promise for every model or server. The result depends on the two models, the hardware, how many requests run together, the input text, and how the model picks each token.

## The full loop

- A small model guesses ahead.
- The large model checks the guesses together.
- The first bad guess ends the accepted prefix.
- A correction keeps the large model's original probability distribution.
- The method is useful only when the cheap guesses save more time than they cost.
